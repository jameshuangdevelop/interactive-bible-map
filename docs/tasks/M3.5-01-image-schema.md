## Goal
Get the data ready for ADR-0029's images: more images per major place, a `kind` for each image, room for the AI reconstructions the project will host, and checks that every image actually loads. Fix the five images that don't load today, Rome's among them.

## Scope
1. **Fix the broken links.** These Commons addresses use the wrong hash folder (`upload.wikimedia.org/wikipedia/commons/<a>/<ab>/<file>`, where `<ab>` is the first two hex digits of the MD5 of the file name with spaces as underscores), so they return 404:
   - `rome.json`: all three images (`1/15` should be `d/d8`; `9/99` → `5/53`; `9/9f` → `6/6e`);
   - `berea.json`: `9/9a` → `7/72`;
   - `tarsus.json`: `3/32` → `3/35`.

   Check each fixed address opens, and that it is the same file as its `sourcePage`.
2. **Location schema:** a required `prominence`, either `"major"` or `"standard"`. Set it on all 89 records: `"major"` for exactly the 31 places in ADR-0029, and `"standard"` for the rest. Emit it to the app's data build.
3. **Media schema:**
   - `images` holds 1 to 10 entries.
   - Each image gets a required `kind`, one of `modern`, `site`, `reconstruction` or `ai-reconstruction`. Fill in `kind` for all existing images from their captions and Commons pages; the batch tasks correct it where needed.
   - `aiGenerated: true` goes with `kind: "ai-reconstruction"` and only with it.
   - **AI entries** have the id `<location-id>-ai-NN` and a `url` of `media/ai/<id>.webp`, a file in the repository, plus `generator` (tool, model and date), `promptRef` (the prompt's heading in `content/image-prompts/<location-id>.md`) and `basedOn` (source ids from the brief). Their `license`, `licenseUrl`, `author` and `sourcePage` rules wait for M3.5-07's licensing decision, so allow them through a narrow, documented branch of the schema that no AI file uses yet. Add `media/ai/` with a `.gitkeep`.
   - Update `schema/README.md`.
4. **Validator rules** (each with a passing and a failing test fixture):
   - every Commons `url` is a plain `https://upload.wikimedia.org/wikipedia/commons/<a>/<ab>/<file>` address, with no query string, whose hash folder matches the MD5 of its file name;
   - the `url`'s file name is the same file as the `sourcePage`'s `File:` name;
   - an AI image's file exists, is WebP, is at most 1,600 px wide and at most 400 KB;
   - a standard place has at most 3 images. A major place with fewer than 5 is a **warning** until the flag `REQUIRE_MAJOR_IMAGES` is turned on (the last batch, M3.5-04, turns it on);
   - every source id cited in square brackets in `content/image-prompts/*.md` resolves, as it would in a location record (`bib:` ids exist in `data/bibliography.json`, and so on), and each file is named after an existing location id.
5. **Online link check:** `npm run check:images` loads every Commons image at each thumbnail width the panel requests (read the panel's Commons thumbnail builder in `app/src/features/place-panel/`), and checks every AI file. Use a clear User-Agent, at most 2 requests at a time, and retries with back-off. It prints a table of failures and exits non-zero if there are any. Add a GitHub Actions workflow that runs it on pull requests that touch `data/media/**` or `media/**`, weekly, and on demand. Run it once now, and fix or list every failure.
6. Run `npm run validate:data` (0 errors), `npm test` and `npm run build:data`, and check that Rome's photos show in the built app (`?place=rome`).

Commit: `data(media): add image kinds and prominence, fix broken links, check every image`.
