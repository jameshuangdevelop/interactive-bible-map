| | |
|---|---|
| People and agents, in order | `fact-checker` (the generator's terms and our license) → `gis-engineer` (the generation script) → `media-curator` and `fact-checker` (the generate–check–revise loop) → **the human** (approves the final set) → `media-curator` (adds them) → `fact-checker` (final report) |
| Models | Claude Opus 5.5 → GPT-5.3-Codex → Claude Sonnet 5 and Claude Opus 5.5 → — → Claude Sonnet 5 → Claude Opus 5.5 |
| Branch | `data/m3.5-ai-images` (from the last merged batch) |
| Depends on | M3.5-02 to M3.5-04 (checked prompts), M3.5-06 (the gallery), and the human's choice of image generator and its API key |

## Goal
Publish AI reconstructions for the major places, made like a historical game's establishing shots and checked against cited research (ADR-0029 §7).

## Steps
1. **Fact-Checker, before any image is made:** read the chosen generator's current terms, and confirm that we may publish its images on a public site for anyone to reuse, including commercially. Decide the license we release them under (CC0 1.0 unless the terms or the law require otherwise), and the credit wording. Record both in `docs/LICENSES.md` and `ATTRIBUTION.md`, and finish the schema's AI fields with the GIS Engineer's rules from M3.5-01. Commit: `docs(licenses): rules for AI-generated reconstructions`.
2. **GIS Engineer:** add `npm run generate:ai -- <prompt-id> [--variants N]`. It reads the prompt's text from its brief (only the paragraph under the heading, never the "Keep out" checklist), calls the chosen generator's API at the largest landscape size it offers, and saves the candidates as `media/ai-incoming/<id>-rN-vK.<ext>`, a folder Git ignores. It reads the API key from a user environment variable and never prints or writes it. It also records the tool, the model, the date and the seed next to each candidate, so the published entry can cite them. Add `npm run publish:ai -- <candidate>`, which converts a candidate to WebP of at most 1,600 px wide and 400 KB at `media/ai/<id>.webp`. Commit: `feat(scripts): generate and publish AI reconstructions`.
3. **The generate–check–revise loop (Media Curator and Fact-Checker):** for each prompt, generate 2 candidates. The Fact-Checker views them against the brief and lists every error, for example a later building, the wrong roofs or walls, the wrong scale, an impossible landscape, modern objects, text, or garbled hands. The Media Curator revises the prompt under the rules in `.github/agents/media-curator.agent.md` and generates again, for up to 3 rounds. If a prompt the Fact-Checker judges good still fails after 3 rounds, stop and report it to the PO. That is the human's signal to change models (ADR-0029 §7), not a reason to keep spending.
4. **The human:** approves the final set from a contact sheet before anything is published.
5. **Media Curator:** publish each approved candidate with `npm run publish:ai`, and add its entry: `kind: "ai-reconstruction"`, `aiGenerated: true`, the generator, the prompt reference, the brief's source ids and a caption starting "AI-generated reconstruction of …". Commit the revised prompts too. Put a place's overview first only if the PO agrees. Commit: `data(media): add AI reconstructions`.
6. **Fact-Checker:** a last check of the published files against their briefs. Report every round, error and fix in `docs/verification/M3.5-ai-images.md`. Commit: `docs(verification): check AI reconstructions`.

## Acceptance criteria
- [ ] The license and credit for AI images are recorded, and every AI image carries the "AI-generated reconstruction" label in the app.
- [ ] Every published AI image passed the Fact-Checker's check against its brief, and the human approved it.
- [ ] No API key appears in the repository, the logs or the PR.
- [ ] `npm run validate:data`, `npm run check:images` and the app checks pass.

## Finish
Each agent follows the session protocol in its agent file; the Fact-Checker's last phase ends the task. PR title: `data(media): AI reconstructions for major places`.
