## 2. Open questions for the Fact-Checker — answered

### Q1. Does combining CC BY, CC BY-SA/ODbL, and CC0 sources into `data/*.json` require the whole release to carry a share-alike license?

**Answer: Split by license family; do not use one blanket license.** ODbL (AWMC, OpenStreetMap) and the Creative Commons licenses are two legally distinct copyleft regimes — the CC BY-SA 4.0 legal code's "BY-SA Compatible License" mechanism (`creativecommons.org/compatiblelicenses` — currently returns 404, i.e. no such list is presently published) and ODbL's own "compatible license" clause (§4.4(a)(iii), opendatacommons.org/licenses/odbl/1-0/) are each closed lists that do not cross-designate the other family. So:
- **`data/geo/`** (geometry *extracted* from AWMC and, where applicable, OpenStreetMap — roads, provinces, coastlines, boundary polygons) is a **Derivative Database** under ODbL §4.4(b) ("Extraction or Re-utilisation of the whole or a Substantial part of the Contents into a new database is a Derivative Database") and **must be released under ODbL 1.0**, with the ODbL notice text (§4.3) and the dataset available for no-charge download (§4.6 — satisfied by hosting it in the public repo).
- **The rest of `data/` and `content/`** (location records, scripture references, routes, timeline, written summaries) is recorded in **`docs/LICENSES.md` as CC BY-SA 4.0**. This satisfies DARE's CC BY-SA 3.0 requirement that Adapted Material be released under "this License, a later version of this License with the same License Elements, or a Creative Commons jurisdiction license... with the same License Elements" (CC BY-SA 3.0 legalcode, §4(b) — confirmed at creativecommons.org/licenses/by-sa/3.0/legalcode, read 2026-09-23) — 4.0 qualifies as "a later version... with the same License Elements" (Attribution + ShareAlike). A share-alike license is strictly compliant with the plainer CC BY 4.0/3.0 terms of OpenBible.info, Pleiades, and the ORBIS dataset (attribution is a subset of what BY-SA already requires), and CC0 Wikidata content folds in without friction.
- Bible text (WEB) stays public domain regardless of the surrounding record's CC BY-SA 4.0 license — the scripture string itself carries no license; only the compiled JSON structure around it does.

### Q2. If we ever cite a figure read directly from the ORBIS web app rather than the CC BY 3.0 dataset, what license applies?

**Answer: Unknown, and now known to be worse than "unknown" for the map background.** The rendered `orbis.stanford.edu` page carries no terms/copyright link; its footer credits its own background tiles as "Tiles © AWMC, CC BY-NC 3.0" — a **non-commercial** license, which Wikimedia Commons and this project's MIT/CC BY-SA stack cannot use at all. **Recommendation:** never read a figure, screenshot, or tile off the live web app; use only the CC BY 3.0 flat-file node/edge dataset (`purl.stanford.edu/mn425tz9757`) and recompute any figure needed from it.

### Q3. If we extract a modern place name or boundary from OSM into our own `data/*.json` records, does that trigger ODbL share-alike, and how should it be scoped?

**Answer: Treat it as ODbL-covered and scope it narrowly.** ODbL's "Produced Work" exception (§4.5(b): "Using this Database... to create a Produced Work does not create a Derivative Database") covers things like a rendered map tile or a search result page, not a new structured database. Storing an OSM-derived name or boundary as a field in our own `data/*.json` is "Extraction... into a new database" (§4.4(b)) — a Derivative Database, regardless of how small the individual fact is; ODbL does not have a facts-are-free carve-out the way copyright does. **Scoping rule:** any field whose value was read from OSM (not independently cross-checked against a CC BY/CC0 source and re-expressed) must (a) live in `data/geo/` or carry an explicit `"sourceLicense": "ODbL-1.0"` marker on that field/array element if it cannot be physically separated, and (b) be covered by the site-wide ODbL attribution notice. Facts we cross-verify across multiple non-ODbL sources and express in our own words (e.g., a coordinate confirmed independently against Pleiades/OpenBible.info) are not OSM extractions and stay under the project's CC BY-SA 4.0 data license.

### Q4. What WEB attribution wording avoids implying eBible.org's endorsement?

**Answer**, based on eBible.org's own statement ("The World English Bible is in the Public Domain... However, 'World English Bible' is a Trademark of eBible.org... if you CHANGE the actual text... you not call the result the World English Bible any more" — <https://ebible.org/find/details.php?id=engwebp>, read 2026-09-23):

> Scripture quotations are from the **World English Bible (WEB)**, a public-domain translation of the Bible (66-book Protestant-canon edition, eBible.org). "World English Bible" is a trademark of eBible.org; this project is not produced, reviewed, or endorsed by eBible.org.

This wording works unmodified for either `engwebp` (US spelling) or `engwebpb` (British/international spelling), since both are public domain with the identical trademark status — only the edition name in parentheses would need to change if the human's CP1 pick is recorded there. Recorded in `docs/LICENSES.md`.

### Q5. Is relying on Pleiades' periodic bulk downloads (rather than the live site) an acceptable long-term citation-verification method?

**Answer: Yes — and it is more current than SOURCES.md's "quarterly" wording suggests.** Per the `isawnyu/pleiades.datasets` README, the complete JSON dump is regenerated **daily**, the RDF (Turtle) dump **weekly**, and only the packaged "numbered release" (e.g., 4.0.1 → 4.1) follows a several-month cadence. This is Pleiades' own sanctioned redistribution channel (the README states it exists "to facilitate reproducibility and to comply with license terms"), so it is an acceptable, indeed preferable, long-term method while `pleiades.stoa.org`'s anti-bot challenge blocks per-page automated fetches. See §3 for the resulting correction to SOURCES.md.
