## 3. Question: does hiding disputed boundaries change any obligation?

**No**, provided the features are hidden **in our hosted style** (a filter or a removed layer), not deleted from the tiles.

1. **ODbL.** Rendering tiles with some features filtered out is still creating a Produced Work, and §4.5(b) says this "does not create a Derivative Database". The style file contains no OpenStreetMap Contents, only drawing rules and URLs. The §4.3 notice (the OpenStreetMap credit linked to `/copyright`) is required exactly as before. No share-alike (§4.4) or access (§4.6) duty arises. *If we ever removed features from the tile data itself and served the result, that modified tileset would be an "alteration" of the database, that is, a Derivative Database: it would have to be released under the ODbL and offered in full or as an alteration file (§4.4, §4.6). So do not do that.*
2. **Style licences.** Changing a filter is one more modification of the style. For Liberty (BSD, MIT, CC BY 3.0/4.0), the "modified" notice we must add anyway (CC BY 4.0 §3(a)(1)(B)) covers it, and we list it. Protomaps and VersaTiles styles are CC0, so nothing is added.
3. **Credits.** The OpenMapTiles, OpenFreeMap, OpenStreetMap and ESA WorldCover credits are unchanged, because the rest of the map still shows their data. The OSMF guidelines allow, but do not require, saying which OpenStreetMap content is used.
4. **For the Frontend Engineer:** in Liberty, remove the `boundary_disputed` layer and keep the existing `disputed`/`claimed_by` exclusions on `boundary_2` and `boundary_3`. In Protomaps, add `["!=", ["get", "disputed"], true]` to `boundaries_country` and `boundaries`. In VersaTiles Colorful, remove `boundary-country-disputed` and the disputed branch of `boundary-country:outline`.
